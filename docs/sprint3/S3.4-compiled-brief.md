# S3.4 — Compiled Oracle Brief

## Purpose

The oracle (large-tier model) is the most expensive tier in the cost-routing stack.
Its token share is the dominant term in the savings identity:

```
reduction ≈ f × (1 − 1/r)
```

where `f` is the fraction of turns handled by the oracle and `r` is the price ratio.
Keeping the oracle's context compact — replacing raw session transcripts with a
structured brief — directly reduces `f` and shrinks each oracle call's token count.

`packages/code-intelligence/src/brief.ts` is the pure assembler that produces
this brief. It accepts structured inputs only; there is no `rawTranscript` field.

---

## OracleBrief shape

```ts
interface OracleBrief {
  text: string            // Plain-text brief the oracle receives
  estimatedTokens: number // estimateTokens(text)
  tokenBudget: number     // Budget applied during assembly
  trimmed: boolean        // True when any slice/attempt was truncated
}
```

---

## Brief schema — section ordering

Sections appear in this fixed order regardless of input size:

| # | Section | Always included? | Trimmed? |
|---|---------|-----------------|---------|
| 1 | `## Problem` | Yes | Never |
| 2 | `## Question` | Yes | Never |
| 3 | `## Expected Output Shape` | Yes | Never |
| 4 | `## Context Slices` | Only when slices are provided | Yes — greedily per slice |
| 5 | `## Prior Attempts` | Only when attempts are present | Yes — as a block |

The oracle therefore always sees the core directive (sections 1–3) before any
supporting context. Sections 4–5 are elided entirely if their budget allocation
reaches zero.

---

## Budget policy

| Parameter | Default | Notes |
|---|---|---|
| Total budget | 8 000 tokens | Override via `BriefInput.tokenBudget` |
| Fixed sections 1–3 | Always included | Consume ~60–120 tokens typically |
| Header overhead reserve | 60 tokens | Structural newlines + headings |
| Slice budget | 60% of remaining | Greedy in input order; each slice gets what's left |
| Attempt budget | 40% of remaining | Trimmed as a single block via smartTruncate |

Token estimation uses `estimateTokens` from `trim.ts` (content-aware char
heuristic, ±10–20%).  The smartTruncate head+tail strategy is used for both
slices and the attempts block, so the most-informative ends are retained even
when the middle is elided.

---

## BriefInput — structured API

```ts
interface BriefInput {
  problem: string               // Problem statement (always emitted)
  question: string              // Specific question for the oracle (always emitted)
  outputShape: string           // Expected output format (always emitted)
  slices: readonly string[]     // Code/context slices (trimmed to budget)
  attempts: readonly AttemptSummary[] // Prior attempts (trimmed to budget)
  tokenBudget?: number          // Defaults to 8 000
}
```

There is no `rawTranscript` field. The API is the enforcement boundary: a caller
cannot inject a raw conversation history without first decomposing it into the
structured fields above.

---

## briefFromContext — convenience adapter

```ts
function briefFromContext(
  recon: ReconBundle,
  canonicalState: CanonicalStateFragment,
  question: string,
  outputShape: string,
  opts?: { problem?: string; tokenBudget?: number },
): OracleBrief
```

Maps the two S3 inputs into `BriefInput` and calls `compileBrief`:

| Source | Mapped to |
|---|---|
| `recon.notes` | Slices (first, highest priority — carry conventions) |
| `recon.entities` | Slices (entity kind + name + file + signature + domain) |
| `recon.references` | Not included (callers visible via entity slices) |
| `canonicalState.attempts[].payload` | `AttemptSummary[]` (task / status / error) |

`CanonicalStateFragment` is a structurally-compatible subset of
`SessionCanonicalState.CanonicalState` — no Effect imports, no DB deps.

## How S3.2 / S3.3 hand off to the oracle

On escalation the risk-escalation router (S3.2) calls `recon(task)` on the
code-intelligence port to get the `ReconBundle`, then reads the session's
`CanonicalState` fragment from S1.3, and passes both to `briefFromContext`:

```
riskRouter (S3.2)
  └─► recon(task)           → ReconBundle
  └─► canonicalState.load() → CanonicalStateFragment
  └─► briefFromContext(...)  → OracleBrief
  └─► oracleCall(brief.text) [token budget enforced]
```

The governance gate (S3.3) sees the same `OracleBrief.text` as its input when
verifying the oracle's proposed edit — not the raw transcript. This keeps the
gate's context window similarly bounded.
