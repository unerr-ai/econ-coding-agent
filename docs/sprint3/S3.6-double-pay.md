# S3.6 — Double-Pay Accounting

**Date:** 2026-06-27
**Status:** implemented — pure module + test, no router wiring yet (S3.2 wires it).

---

## Why double-pay matters

When the risk-escalation router (S3.2) decides mid-turn that the cheap conductor
cannot handle a task and invokes the oracle, two model calls are billed for one
logical turn: the cheap attempt **and** the oracle response.  Reporting only oracle
cost makes savings look better than they are.  This module records both costs so
the S7 savings receipt can subtract the wasted spend and show an honest net figure.

---

## Event shape — `EscalationCost`

```typescript
interface EscalationCost {
  turnId: string

  cheap: {
    tier: "cheap"
    model: string          // e.g. "qwen/qwen-2.5-coder-32b-instruct"
    cost: number           // USD; sourced from Usage.cost (S0.3)
    tokens: {
      input: number
      output: number
      cacheRead?: number
      cacheWrite?: number
    }
  }

  oracle: {
    tier: "oracle"
    model: string          // e.g. "anthropic/claude-opus-4"
    cost: number
    tokens: { input: number; output: number; cacheRead?: number; cacheWrite?: number }
  }

  totalCost: number        // cheap.cost + oracle.cost — the honest per-turn bill
  wastedCost: number       // cheap.cost — money burned on the discarded attempt
}
```

**Invariants (always true):**
- `totalCost === cheap.cost + oracle.cost`
- `wastedCost === cheap.cost`

## Module API — `packages/code-intelligence/src/double-pay.ts`

### `recordEscalation(input: EscalationInput): EscalationCost`

Builds the record and calls an optional `emit` callback synchronously.  Pure
function — no I/O.  The router calls this inside the escalation branch after the
oracle response arrives (both costs are then known).

```typescript
const record = recordEscalation({
  turnId: session.currentTurnId,
  cheap:  { model: cheapModel,  cost: cheapUsage.cost ?? 0,  tokens: cheapTokens  },
  oracle: { model: oracleModel, cost: oracleUsage.cost ?? 0, tokens: oracleTokens },
  emit:   (r) => emitSavingsEvent("escalation", r),   // injected at wiring time
})
```

### `DoublePayLedger`

In-memory aggregator.  One instance per session; the router (S3.2) adds every
escalation record.

```typescript
const ledger = new DoublePayLedger()
ledger.add(record)            // called by the router on each escalation

ledger.escalations            // count of escalated turns
ledger.totalWastedCost        // Σ cheap.cost across all escalations
ledger.effectiveSavings(gross) // gross − totalWastedCost → honest net
ledger.snapshot()             // { escalations, totalWastedCost } — safe to log
```

## Wiring point — S3.2 router

Inside the escalation branch of the cost-routing engine (the point where S3.2
decides the cheap model's answer is insufficient and the oracle must re-answer),
add:

```typescript
import { recordEscalation } from "@opencode-ai/code-intelligence/src/double-pay.ts"

// After oracle responds:
const record = recordEscalation({
  turnId:  turn.id,
  cheap:   { model: cheapModel, cost: cheapStep.cost ?? 0, tokens: cheapStep.tokens },
  oracle:  { model: oracleModel, cost: oracleStep.cost ?? 0, tokens: oracleStep.tokens },
  emit:    sessionLedger.add.bind(sessionLedger),   // or inject emitSavingsEvent here
})
```

`cheapStep.cost` comes from `SessionEvent.Step.Ended.cost`, which S0.3 wired to
`Usage.cost` flowing from the OpenRouter wire.

## S7 savings receipt — subtracting double-pay

The receipt accumulates gross savings (oracle reference price minus cheap price) for
every turn that **succeeded** on the cheap model.  Before displaying:

```typescript
const display = {
  grossSavings:     router.grossSavings,
  doublePayPenalty: sessionLedger.totalWastedCost,
  effectiveSavings: sessionLedger.effectiveSavings(router.grossSavings),
  escalations:      sessionLedger.escalations,
}
```

`effectiveSavings` can go negative in a pathological session (many escalations,
few cheap successes) — the receipt should surface that honestly rather than clamp
to zero, so users can see the router performing poorly.

## Dependency boundary

- **No imports from `packages/core` or `packages/llm`.** Callers extract the
  `cost` / token numbers from `Usage` and pass plain values — the accounting module
  stays decoupled.
- **No I/O.** `emit` is pluggable; the default (omitted) is a no-op.
- **`packages/code-intelligence/src/index.ts` not modified** — import by path
  (`../src/double-pay.ts`) until the index export is coordinated with S3.1/S3.4.
