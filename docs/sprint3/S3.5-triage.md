# S3.5 — Per-Repo Triage: Go/No-Go on Cheap-First Routing

## Purpose

Before any session starts, decide whether cheap-first routing pays for **this specific repo**.
Rather than blindly defaulting to the conductor tier, `triageRepo` checks whether observed
pass-rate data and signal quality together justify the cheap-first bet.

Module: `packages/code-intelligence/src/triage.ts`

---

## Go/No-Go Inequality

Cheap-first routing pays iff **all three** conditions hold:

```
cheapPassRate > 1 / costRatio          (pass-rate clears the break-even point)
signalDiscrimination >= 0.6            (risk signal separates pass from fail)
sampleSize >= 30                       (statistics are reliable)
```

### Why `cheapPassRate > 1/costRatio`

Expected cost per turn under cheap-first routing:

```
E[cost] = cheapPassRate × C_cheap + (1 − cheapPassRate) × C_oracle
```

Cheap-first beats oracle-first (`C_oracle`) when `E[cost] < C_oracle`, which simplifies to:

```
cheapPassRate × C_cheap < cheapPassRate × C_oracle
cheapPassRate > C_cheap / C_oracle
cheapPassRate > 1 / costRatio
```

So `1/costRatio` is the **break-even pass-rate**. Below it, routing costs more than just always
using the oracle.

### Why `signalDiscrimination >= 0.6`

The pass-rate inequality tells us *how often* cheap works. The discrimination check tells us
whether our risk signal can *predict* when cheap will fail — without that, we can't selectively
escalate and the router degrades to a coin flip. 0.6 is set above random (0.5) with a margin;
a perfect predictor scores 1.0.

### Why `sampleSize >= 30`

Both `cheapPassRate` and `signalDiscrimination` are estimated from observed data. Fewer than 30
turns makes both estimates unreliable. Below this floor the triage falls back to degrade-open.

---

## Degrade-Open Rule

**On any missing or degenerate signal → default to cheap-first, never crash.**

Triggers:
- Any stat is `NaN` or `Infinity`
- `sampleSize < 1` (zero or negative: no data at all)
- `sampleSize < MIN_SAMPLE_SIZE` (too few samples to trust)
- `costRatio <= 0` (degenerate: would cause division by zero)

Return: `{ decision: "cheap-first", reason: "insufficient signal" }`

Rationale: we never have enough information to confidently force the oracle at repo
initialisation. Defaulting cheap is safe — the per-turn risk router still escalates
individual high-risk turns. Forcing oracle on bad data would silently drain savings.

---

## How It Feeds `routeTurn`

`triageRepo` returns `{ decision, forceTier?, reason }`. The `forceTier` field is designed to
pass directly into `routeTurn`'s existing S3.5 override hook:

```typescript
const triage = triageRepo(repoStats)

const routeOutput = routeTurn({
  risk: currentRisk,
  state: sessionState,
  forceTier: triage.forceTier,   // "oracle" when oracle-first, undefined when cheap-first
})
```

When `forceTier` is `"oracle"`, `routeTurn` bypasses all hysteresis and risk logic and returns
the oracle tier immediately (evaluation step 1 in router.ts). When `forceTier` is `undefined`
(cheap-first), normal hysteresis applies and per-turn risk still drives escalation.

---

## API Summary

```typescript
triageRepo(stats: TriageStats, options?: { minSampleSize?: number; minDiscrimination?: number })
  → TriageResult

interface TriageStats {
  cheapPassRate: number          // 0–1
  costRatio: number              // oracle / conductor cost ratio (e.g. 5)
  signalDiscrimination: number   // 0–1 AUC / separation score
  sampleSize: number             // number of observed turns
}

interface TriageResult {
  decision: "cheap-first" | "oracle-first"
  forceTier?: "oracle"           // set only when oracle-first
  reason: string
}
```

Default thresholds (overridable via `options`):
- `MIN_SAMPLE_SIZE = 30`
- `MIN_DISCRIMINATION = 0.6`
