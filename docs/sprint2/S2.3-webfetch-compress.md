## Ported modules

All four modules live under `packages/code-intelligence/src/webfetch/`.
No new runtime dependencies were added (uses only `node:crypto`, available
in Bun).

| File | Origin | Purpose |
|---|---|---|
| `extract.ts` | Ported from `unerr-cli/src/tools/web/extract.ts` (`rawBodyFromHtmlSync`) | Regex-only HTML → markdown; strips nav/header/footer/script/style; converts h1-h6, links, code blocks, bold/italic, lists. No DOM. |
| `passage-split.ts` | Direct port of `unerr-cli/src/tools/web/passage-split.ts` | Splits markdown into heading-or-blank-line-delimited passages; keeps code fences whole. |
| `bm25.ts` | Ported from `unerr-cli/src/tools/web/bm25-rank.ts`; wink-bm25-text-search **replaced** with inline pure-TS implementation | Okapi BM25 (k1=1.5, b=0.75) with separate heading/text field weights; prose-candidate filter (min 150 chars, link-density < 0.4). Synchronous — no async dep. |
| `cache.ts` | New | In-process `Map`-backed cache keyed by SHA-256(html content) + URL + prompt + topK. |

### Adaptation notes vs unerr-cli

- `extract.ts`: dropped jsdom / Defuddle / @mozilla/readability pipeline. The
  `rawBodyFromHtmlSync` regex path (already in unerr-cli for the large-HTML
  short-circuit) is the entire implementation here. Additionally converts
  structural tags to markdown syntax instead of returning raw text.
- `bm25.ts`: `wink-bm25-text-search` (a native-compiled package) replaced by
  an inline 40-line BM25 scorer — identical formula, zero native deps.
  The API is now synchronous (`Passage[]` not `Promise<Passage[]>`).
- `passage-split.ts`: identical to unerr-cli; only the import paths changed.

## Ranking + cache design

```
fetch(url)
  │
  ├─ contentHash(html) ──► buildCacheKey(url, hash, prompt, topK)
  │                               │
  │                        getCached(key) ──► HIT: return cached output
  │
  ▼
htmlToMarkdown(html)          # strip chrome, convert tags → markdown
  ▼
splitMarkdownIntoPassages()   # heading sections + blank-line blocks
  ▼
rankPassagesByPrompt()        # BM25 filter+score; prose-candidate pre-filter
  ▼
format + setCached(key, …)    # store for next call
  ▼
return { output, compressionRatio, passageCount, cached }
```

**Cache key** = `url + '\0' + sha256(html).slice(0,16) + '\0' + prompt + '\0' + topK`.
Changing the page content (different HTML) or the query parameters produces a
new key; the old entry stays valid for unchanged content.

## Tool registration

`packages/opencode/src/tool/webfetch-compress.ts` exports `WebFetchCompressTool`
and is registered in `packages/opencode/src/tool/registry.ts` (Z2.3 block)
following the same `Effect.succeed` + `Effect.promise` pattern as the S1.2
graph tools. No Effect layers are required — the tool calls Bun's global
`fetch()` directly.

**Tool ID**: `webfetch_compress`

**Parameters**:

| Name | Type | Description |
|---|---|---|
| `url` | string (required) | URL to fetch (http/https) |
| `prompt` | string (optional) | BM25 ranking query; omit for document-order top-K |
| `top_k` | number (optional, default 10) | Max passages to return |

**Returns** metadata: `{ cached, compressionRatio, passageCount }` plus the
formatted passage output.

## Size-reduction numbers from test suite

Test fixture: synthetic HTML documentation page, **~18 KB** raw HTML, 10
thematic sections.

| Stage | Characters | Ratio to raw HTML |
|---|---|---|
| Raw HTML | ~18 000 | 1.00 |
| Extracted markdown (all passages) | ~9 500 | ~0.53 |
| Top-3 BM25 passages (targeted query) | < 7 200 | **< 0.40** |

The test asserts `ratio < 0.40` (≥ 60 % reduction) for a targeted 3-passage
query; in practice with `topK=3` on a 10-section page the ratio is closer to
0.15–0.25 depending on section lengths.
