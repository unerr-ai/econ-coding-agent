# S2.6 — Semantic Layer: `@sem` domain/role in the code graph

## What was built

The code-intelligence graph now parses `@sem domain=<tag> role=<tag>` annotations from
doc comments and stores them as first-class columns on every indexed entity. All query
outputs (`getEntity`, `search`, `recon`, tool JSON) carry `domain` and `role` so agents
reason over meaning, not just names.

---

## `@sem` parse rules

### Comment form

Place a `/** ... */` block comment directly above the entity declaration (no blank line
between the `*/` and the `export`/`function`/`class` keyword).

```typescript
/**
 * One-to-two sentence prose summary — what the entity does and why.
 * Never restate the entity name; never describe the how.
 *
 * @sem domain=<tag> role=<tag>
 */
export function myEntity(...) { ... }
```

Single-line form is also accepted:

```typescript
/** Short summary. @sem domain=<tag> role=<tag> */
export function myEntity(...) { ... }
```

### `@sem` line grammar

```
@sem domain=<word> role=<word>
```

- Both `domain` and `role` are single words (no spaces, no quotes).
- The `@sem` line may appear anywhere inside the block comment.
- Other `@`-tag lines (`@param`, `@returns`, etc.) are ignored by the parser.
- If `domain` is absent the entity is stored with `domain = NULL`.
- If `role` is absent the entity is stored with `role = NULL`.

### Extraction algorithm (`extractDocComment` in `ast-extractor.ts`)

1. Walk backward from the entity's line index, skipping blank lines.
2. Require the nearest non-blank line to end with `*/` (block comment close).
3. Walk further back to find the opening `/**`.
4. Strip comment markers (`/**`, ` * `, `*/`) from each interior line.
5. Match `/domain=(\S+)/` and `/role=(\S+)/` on any line starting with `@sem`.
6. Return `{ semDomain, semRole }` (both optional).

## Schema additions (`bun-sqlite-graph.ts`)

Two nullable TEXT columns were added to the `entities` table:

```sql
domain  TEXT,   -- @sem domain=<tag>
role    TEXT,   -- @sem role=<tag>
```

### Migration

The constructor runs:

```typescript
try { db.exec("ALTER TABLE entities ADD COLUMN domain TEXT") } catch {}
try { db.exec("ALTER TABLE entities ADD COLUMN role TEXT") } catch {}
```

This is a no-op for new (in-memory) DBs where the columns are already in the
`CREATE TABLE` statement, and safely adds the columns to any existing persistent DB.

### Upsert

The `index()` upsert now includes `domain` and `role` in both the INSERT column list
and the `ON CONFLICT DO UPDATE SET` clause, so re-indexing keeps annotations current.

## How reads and recon carry domain/role

### `Entity` type (`index.ts`)

```typescript
export interface Entity {
  // ... existing fields ...
  domain?: string   // @sem domain tag, undefined when not annotated
  role?: string     // @sem role tag, undefined when not annotated
}
```

### `rowToEntity` (`bun-sqlite-graph.ts`)

Maps `domain` and `role` columns from the SQLite row to the `Entity` shape:

```typescript
domain: row["domain"] ? String(row["domain"]) : undefined,
role:   row["role"]   ? String(row["role"])   : undefined,
```

### Query methods

| Method | domain/role present? |
|---|---|
| `getEntity(key)` | Yes — via `rowToEntity` |
| `search(query)` | Yes — via `rowToEntity` |
| `recon(task)` | Yes — entities returned by `search` carry the tags |
| `makeReconTool` JSON output | Yes — serialised by `JSON.stringify(bundle)` |
| `makeFileReadTool` entity profile | Yes — `getEntity` result JSON |
| `makeGetReferencesTool` | N/A — returns `Reference` edges, not entities |

## Tests (`test/semantic.test.ts`)

Fixture: `test/fixture/sem.ts` — two annotated exports (`computeRisk` with
`domain=risk role=analysis`, `ModelRouter` with `domain=routing role=decision`) and one
unannotated export (`unannotated`).

Test assertions:
- `getEntity("computeRisk")` → `domain="risk"`, `role="analysis"`
- `getEntity("ModelRouter")` → `domain="routing"`, `role="decision"`
- `getEntity("unannotated")` → `domain=undefined`, `role=undefined`
- `getEntity("greet")` (existing fixture, no annotation) → both undefined
- `search("computeRisk")` → first result carries tags
- `recon("risk analysis")` bundle → matched entity carries tags
- `makeReconTool` JSON output → serialised `domain`/`role` fields present
