# S0.4 — Plugin gate at the edit boundary

**Spike goal:** prove that an OpenCode plugin can ENFORCE at the edit boundary —
a `tool.execute.before` hook that blocks a designated test edit by throwing, and
the model sees the refusal as a tool error.

**Status:** demonstrated. All 5 verification tests pass.

---

## 1. Hook signature

File: `packages/plugin/src/index.ts`, lines 266–269

```typescript
"tool.execute.before"?: (
  input: { tool: string; sessionID: string; callID: string },
  output: { args: any },
) => Promise<void>
```

- `input.tool` — the tool ID string (e.g. `"write"`, `"edit"`, `"apply_patch"`, `"bash"`)
- `input.sessionID` / `input.callID` — tracing handles
- `output.args` — the raw arguments object the tool was called with (mutable — you can also sanitise/rewrite args here before the tool runs)

The hook is `async`; returning normally allows the tool call to proceed. **Throwing
(or returning a rejected Promise) blocks the tool call.**

---

## 2. How throwing surfaces to the model

**Execution chain** (all in the same Effect run):

```
tool execute()                          packages/opencode/src/session/tools.ts:95–125
  └─ plugin.trigger("tool.execute.before", ...)   tools.ts:99
       └─ Effect.promise(async () => fn(input, output))   plugin/index.ts:290
            └─ hook throws Error(msg)
                 └─ Effect.promise captures rejection → Effect failure
                      └─ propagates through Effect.gen → run.promise rejects
                           └─ AI SDK tool executor catches rejected Promise
                                └─ returns tool error result to the model
```

The model receives a tool-call error part whose `output` string is the thrown
`Error.message`. The model cannot proceed with the blocked edit; it must respond
to the refusal and choose a different action.

Key source line:

```typescript
// packages/opencode/src/plugin/index.ts:290
yield* Effect.promise(async () => fn(input, output))
```

`Effect.promise` wraps any throw/rejection into an Effect failure. Because the
caller does `yield*` inside `Effect.gen`, the failure short-circuits the rest of the
generator and propagates out through `run.promise()` as a plain rejected Promise.
The AI SDK's tool executor converts that into a `tool-error` message part.

## 3. Plugin load mechanism

OpenCode discovers plugins from **two** sources at startup, in order:

| Priority | Source | Path |
|----------|--------|------|
| 3 | Global plugin dir | `~/.config/opencode/plugins/*.{ts,js}` |
| 4 | Project plugin dir | `.opencode/plugins/*.{ts,js}` ← spike lives here |

And from `opencode.json` / `~/.config/opencode/opencode.json`:

```json
{ "plugin": ["my-npm-plugin", "./path/to/local.ts"] }
```

Discovery code: `packages/opencode/src/config/plugin.ts:18–30`
```typescript
export async function load(dir: string) {
  const plugins: ConfigPluginV1.Spec[] = []
  for (const item of await Glob.scan("{plugin,plugins}/*.{ts,js}", {
    cwd: dir, absolute: true, dot: true, symlink: true,
  })) {
    plugins.push(pathToFileURL(item).href)
  }
  return plugins
}
```

A plugin file must export one or more **functions** (the legacy format) or a
`PluginModule` with a `.server` method (the v1 format). The spike uses the
legacy format — every exported async function is called with `PluginInput` and
must return a `Hooks` object.

```typescript
// legacy format — detected by plugin/index.ts:getLegacyPlugins
export const MyPlugin = async (ctx) => {
  return { "tool.execute.before": async (input, output) => { ... } }
}
```

## 4. Spike plugin location

```
.opencode/plugins/econ-gate-spike.js
```

The plugin blocks `write`, `edit`, and `apply_patch` calls whose `output.args.filePath`
contains the string `ECON_GATE_BLOCKED`. Change the marker or replace the predicate
with real governance rules (protected path set, regex, permission check) for production.

### To see the refusal inside a live OpenCode session

1. Start OpenCode in the repo root (where `.opencode/plugins/` is discovered).
2. Ask the model: `"Write the string 'hello' to the file docs/sprint0/ECON_GATE_BLOCKED.txt"`.
3. The model will call `write` with `filePath: "docs/sprint0/ECON_GATE_BLOCKED.txt"`.
4. The gate throws before the tool executes; the model sees a tool error:
   `[econ-gate] REFUSED: 'write' on '...' blocked by governance gate`.
5. The model is forced to respond to the refusal — it cannot complete the write.

## 6. Production path

Replace the path-marker predicate with:
- A set of read-only protected paths (config loaded in the plugin's init `ctx.project`)
- A regex matching generated files, vendored code, or lock files
- A permission check against the session's agent role

The gate fires synchronously inside the Effect graph — latency is sub-millisecond
for simple predicates. For async checks (e.g. a remote policy service), await
inside the hook; the Effect.promise wrapper keeps the caller fully awaited.
