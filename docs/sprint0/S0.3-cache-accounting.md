# S0.3 — Cache Accounting Gate (DAY-0)

**Date:** 2026-06-27  
**Verdict:** `cache.read` works; `cache.write` was broken (fixed); `cost` was hardcoded 0 (fixed).

---

## Trace

### 1. `Usage` type — `packages/llm/src/schema/events.ts:51–60`

Fields as shipped:
```
inputTokens, outputTokens, nonCachedInputTokens,
cacheReadInputTokens, cacheWriteInputTokens,
reasoningTokens, totalTokens, providerMetadata
```
All optional. No `cost` field — **cost was structurally absent from Usage**.

**Fix applied:** Added `cost: Schema.optional(Schema.Number)` at line 58.

---

### 2. Provider wire schema — `packages/llm/src/protocols/openai-chat.ts:115–129`

`OpenAIChatUsage` parsed the SSE final chunk. Before the fix:

```typescript
prompt_tokens_details: optionalNull(Schema.Struct({
  cached_tokens: Schema.optional(Schema.Number),   // cache READ ✓
  // cache_write_tokens missing                    // cache WRITE ✗
})),
// no top-level cost field                         // cost ✗
```

Confirmed from real OpenRouter fixture (`openrouter-streams-text.json`, `openrouter-claude-opus-4-7-drives-a-tool-loop.json`) — OpenRouter returns:

```json
{
  "cost": 4.95e-06,
  "prompt_tokens_details": {
    "cached_tokens": 0,
    "cache_write_tokens": 0,
    ...
  }
}
```

Key findings from fixtures:
- OpenRouter uses `prompt_tokens_details.cached_tokens` for **cache reads** (same as OpenAI native) → already captured correctly.
- OpenRouter uses `prompt_tokens_details.cache_write_tokens` for **cache writes** (NOT `cache_creation_input_tokens` from Anthropic native) → was silently dropped.
- OpenRouter returns a top-level `usage.cost` (USD float) → was not captured.
- OpenRouter also returns `usage.cost_details.upstream_inference_cost` for further breakdown (not captured, not needed for the gate).

**Fix applied:** Added `cost: Schema.optional(Schema.Number)` at the top level and `cache_write_tokens: Schema.optional(Schema.Number)` inside `prompt_tokens_details`.

---

### 3. `mapUsage` function — `packages/llm/src/protocols/openai-chat.ts:383–397`

Before fix: mapped `cached_tokens → cacheReadInputTokens` but ignored `cache_write_tokens` and `cost`.

**Fix applied:** Now captures both:
```typescript
const cacheWrite = usage.prompt_tokens_details?.cache_write_tokens
// ...
cacheWriteInputTokens: cacheWrite,
cost: usage.cost,
```

---

### 4. `publish-llm-event.ts` — `packages/core/src/session/runner/publish-llm-event.ts:401`

The `step-finish` handler always published `cost: 0`:

```typescript
yield* events.publish(SessionEvent.Step.Ended, {
  finish: event.reason,
  cost: 0,          // ← hardcoded, never computed
  tokens: tokens(event.usage),
})
```

The `tokens()` helper at line 17–27 already correctly reads `cacheReadInputTokens` and `cacheWriteInputTokens` from `Usage` — that path was fine.

**Fix applied:** Changed to `cost: event.usage?.cost ?? 0`. When the provider (OpenRouter) populates `Usage.cost`, it flows through. For providers that don't (native OpenAI, Anthropic direct, Bedrock), it stays 0 — those either don't expose cost in the stream or compute it server-side.

## Verdict

| Field | Before | After | Notes |
|---|---|---|---|
| `cache.read` (`cacheReadInputTokens`) | WORKS | WORKS | `prompt_tokens_details.cached_tokens` was already captured |
| `cache.write` (`cacheWriteInputTokens`) | BROKEN (always 0) | FIXED | OpenRouter field is `cache_write_tokens`, not `cache_creation_input_tokens` |
| `cost` | BROKEN (hardcoded 0) | FIXED | OpenRouter returns `usage.cost`; now flows through Usage → SessionEvent |

**OpenRouter-specific note:** The `openrouter.ts` provider sends `stream_options: { include_usage: true }` (from `fromRequest` in `openai-chat.ts:352`) which is the OpenAI-standard way to get usage in the final SSE chunk. No `usage: { include: true }` body option is needed for the basic token+cost fields — that option only unlocks additional OpenRouter-specific analytics (`cost_details`). The fixtures confirm usage is returned without it.
