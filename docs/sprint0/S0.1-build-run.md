## 4. Model resolution — how it works

**File:** `packages/core/src/session/runner/model.ts`

### `resolve()` — lines 157–165

```typescript
export const resolve = (
  session: SessionSchema.Info,
  model: ModelV2.Info,
  connection?: IntegrationConnection.Info,
  credential?: Credential.Info,
) =>
  withVariant(model, session.model?.variant).pipe(
    Effect.flatMap((model) => fromCatalogModel(model, connection, credential)),
  )
```

Takes the catalog `ModelV2.Info` for the session's selected model, applies the requested variant (e.g. `high`, `low`), then hands it to `fromCatalogModel`.

### `fromCatalogModel()` — lines 115–155

Dispatches on `model.api.type` + `model.api.package`:

| `api.package` | Protocol used | Auth |
|---|---|---|
| `@ai-sdk/openai` | `OpenAIResponses.route` | Bearer |
| `@ai-sdk/anthropic` | `AnthropicMessages.route` | `x-api-key` header |
| `@ai-sdk/openai-compatible` (url required) | `OpenAICompatibleChat.route` | Bearer |

Any other value → `UnsupportedApiError`. The `supported()` guard at line 167 enforces this same set.

`model.api.url` becomes the `endpoint.baseURL` passed into the route (lines 79–81 in `withDefaults()`). The API key comes from (in order): oauth/key credential, inline `request.body.apiKey`, or an env-var connection name.

### `locationLayer` — lines 174–207

This is the runtime wiring. On every session turn it:
1. Reads the catalog (`Catalog.Service`) — populated by provider plugins at startup from `opencode.json` + credentials.
2. Finds the selected model by `providerID` + `id`. Falls back to the first `supported()` model in the catalog if none is configured.
3. Looks up the integration connection (credentials stored in `~/.local/share/opencode/auth.json`).
4. Calls `resolve()` above.

### How config maps to a model

`opencode.json` key `"model": "openrouter/qwen/qwen3-coder-480b-a35b"` is parsed as `providerID=openrouter`, `modelID=qwen/qwen3-coder-480b-a35b`. The catalog locates the matching `ModelV2.Info` (which carries `api.package`, `api.url`, `api.id`, etc.) and `resolve()` builds the LLM call object from it.

## 5. Config to point a tier at an OSS OpenAI-compatible endpoint

### Option A — OpenRouter (preloaded provider, easiest)

OpenRouter is already in the catalog. You only need an API key.

**Step 1.** Either run `/connect` in the TUI and select OpenRouter, or set the env var:
```bash
export OPENROUTER_API_KEY=sk-or-v1-...
```

**Step 2.** Create/update `opencode.json` in your project (or `~/.config/opencode/opencode.json` globally):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/qwen/qwen3-coder-480b-a35b"
}
```

That's it. Any OpenRouter model ID listed on [openrouter.ai/models](https://openrouter.ai/models) works — format is `openrouter/<author>/<model-slug>`.

To add an OpenRouter model that isn't preloaded:
```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/qwen/qwen3-coder-480b-a35b",
  "provider": {
    "openrouter": {
      "models": {
        "qwen/qwen3-coder-480b-a35b": {}
      }
    }
  }
}
```

### Option B — Local vLLM (or any OpenAI-compatible server)

For a local vLLM instance (or Ollama, LM Studio, llama.cpp, etc.):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local-vllm/qwen2.5-coder-32b-instruct",
  "provider": {
    "local-vllm": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Local vLLM",
      "options": {
        "baseURL": "http://localhost:8000/v1",
        "apiKey": "ignored"
      },
      "models": {
        "qwen2.5-coder-32b-instruct": {
          "name": "Qwen2.5-Coder 32B",
          "limit": {
            "context": 131072,
            "output": 8192
          }
        }
      }
    }
  }
}
```

Key fields:
- **`npm`**: must be `@ai-sdk/openai-compatible` for `/v1/chat/completions`. Use `@ai-sdk/openai` only if the endpoint uses `/v1/responses`.
- **`options.baseURL`**: full URL including `/v1`. No trailing slash.
- **`options.apiKey`**: can be any string for local endpoints (or `"{env:MY_ENV_VAR}"` syntax for environment-variable injection).
- **`limit.context` / `limit.output`**: not auto-discovered for custom providers — set these to what your model supports so context tracking works.
- The model ID in the `models` map must match exactly what the server returns in `GET /v1/models`.

**Run command with this config:**
```bash
opencode run -m local-vllm/qwen2.5-coder-32b-instruct "say hello in one line"
```

### Option C — OpenRouter via custom provider block (explicit control)

If you want to override the preloaded OpenRouter provider (e.g., set request-level provider routing):
```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/qwen/qwen3-coder-480b-a35b",
  "provider": {
    "openrouter": {
      "options": {
        "apiKey": "{env:OPENROUTER_API_KEY}"
      },
      "models": {
        "qwen/qwen3-coder-480b-a35b": {
          "options": {
            "provider": {
              "order": ["DeepInfra", "Together"],
              "allow_fallbacks": false
            }
          }
        }
      }
    }
  }
}
```

The desktop Electron app is not needed for the econ agent harness (we target the CLI/HTTP API path), so this is low priority.
