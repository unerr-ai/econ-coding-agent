## On the umbrella `bun turbo build`

`turbo.json` `build` has `dependsOn: []`, so the umbrella build runs every package's
build in parallel. Two targets fail — **both pre-existing at the pinned upstream commit
and both non-shipped by econ** (we never touched either):

1. **`@opencode-ai/sdk`** — its `build` runs `@hey-api/openapi-ts` with `clean: true`,
   which **deletes and regenerates** the committed `src/v2/gen/*` files from an
   `openapi.json` produced by `bun dev generate`. This regenerate is destructive and
   fragile (if interrupted it corrupts the tracked gen files; restore with
   `git checkout -- packages/sdk`). The committed generated sources are valid and the
   product builds against them — we do **not** need to regenerate the SDK to ship.
2. **`@opencode-ai/desktop`** — Electron app, expects a `packages/opencode/dist/node/`
   layout the Bun executable build doesn't emit. econ drives the CLI/HTTP API, not the
   desktop app.

**Verification scope = what econ ships**: the `opencode` server/CLI binary + typecheck
across the workspace + our new `code-intelligence` package. All green. The two broken
umbrella targets are tracked as upstream baggage, not econ regressions.
