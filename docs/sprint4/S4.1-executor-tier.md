# S4.1 — Executor Tier + Tool-Call Validation

**Module:** `opencode.json` agents + `.opencode/plugins/econ-executor-validate.js`  
**Sprint:** 4 (stateless cheap tier)  
**Status:** shipped

---

## What it is

A cheap, stateless ~9B tool-calling model (`executor` tier) added to opencode.json that
handles delegable, read-only or mechanical tasks without reasoning overhead. Paired with a
pre-dispatch schema-validation plugin that catches malformed tool calls from the cheap
model before they reach execution, so the model self-corrects and retries with valid args.

---

## The executor agent in opencode.json

```json
{
  "agents": {
    "executor": {
      "model": "openrouter/qwen/qwen3-8b",
      "description": "econ executor tier: cheap ~9B stateless tool-caller for delegable executor-tier specialists",
      "mode": "subagent"
    }
  }
}
```

**Key properties:**

- **Model:** Qwen3-8B (~9B params) or any small tool-calling OSS model on OpenRouter
- **Mode:** `subagent` — spawned per-task via OpenCode's `task` tool (never the primary session agent)
- **Role:** handles recon, lint, docstrings specialists; returns a DIGEST (S4.3)
- **Cost:** ~100x cheaper than frontier models, no reasoning needed

## Pre-dispatch schema validation plugin

**File:** `.opencode/plugins/econ-executor-validate.js`

### Plugin load mechanism

OpenCode auto-discovers all `*.js` files under `.opencode/plugins/` at startup
(packages/opencode/src/config/plugin.ts). Each exported function is called with a
`PluginInput` context and must return a `Hooks` object with promise-based handlers.

### Hook contract: `tool.execute.before`

From packages/plugin/src/index.ts:266:

```typescript
"tool.execute.before"?: (
  input:  { tool: string; sessionID: string; callID: string },
  output: { args: any }
) => Promise<void>
```

Fires **before dispatch** on every tool call, with the tool name and its call arguments.

### Enforcement mechanism: throw to refuse

**Throwing synchronously inside the hook causes the effect to reject** (plugin/index.ts:290),
which propagates up through `run.promise` and surfaces to the AI SDK as a **tool call error
the model sees in its next turn**. The model can then self-correct and retry with valid
arguments — no human intervention needed.

```javascript
throw new Error("[econ-executor-validate] REFUSED: '${tool}' call has a malformed schema: ...")
// ↓ AI SDK receives error
// ↓ model self-corrects
// ↓ retries tool call with valid args
```

### Schema validation logic

Validates required fields + types for: `read`, `edit`, `write`, `bash`, `grep`, `glob`, `task`.

**Per-tool schema:** Each tool declares required fields with accepted camelCase / snake_case
aliases and expected type (always `string` for executor tools):

| Tool | Required fields | Aliases |
|------|----------|---------|
| `read` | `filePath` | filePath \| file_path |
| `edit` | filePath, oldString, newString | file_path, old_string, new_string |
| `write` | filePath, content | file_path |
| `bash` | `command` | — |
| `grep` | `pattern` | — |
| `glob` | `pattern` | — |
| `task` | description, prompt, subagent_type | — |

**Validation rules:**

1. Args must be a plain object (not null, array, or primitive)
2. Every required field must be present (under any accepted alias)
3. Every required field must be the expected type (string)
4. No empty strings (`.trim() === ""` fails)

**Tools not in the schema table pass through untouched** — no validation overhead for
tools that aren't listed.

---

## Error reporting to the model

When validation fails, the error message is precise and actionable:

```
[econ-executor-validate] REFUSED: 'read' call has a malformed schema: 
'filePath|file_path' is missing; 'oldString|old_string' must be a string, got undefined. 
Required: filePath, oldString, newString. Fix the arguments and retry.
```

The model sees this and typically self-corrects immediately — no looping or degradation.

---

## Integration

The plugin is **auto-loaded by OpenCode** at startup. No registration call needed.

The validator fires on **every tool call from any model**, so it applies to:
- Executor specialists (primary beneficiary — cheap models make more mistakes)
- Worker specialists (backup — catches rare errors from mid-tier models)
- Any subagent running on the conductor or executor tier

## Done-when
